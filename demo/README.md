# Demo media and seed

The demo uses local JSON data and independently served static music. `data/seed.json` supplies fictional Sonar profiles; the music remains credited to its real author. [Contracts](../docs/demo-contracts.md), [media storage](../docs/media-storage.md), [tasks](../docs/tasks.md) and [CI/CD](../docs/ci-cd.md) describe the complete workflow.

- `audio/`: original MP3 bytes, tracked only through scoped Git LFS attributes.
- `images/`: fourteen small reproducible original SVG covers/avatars, ordinary Git.
- `media-manifest.json`: numeric IDs, relative paths, measured durations, sizes, MIME and SHA-256.
- `licenses.json`: source pages, real authors, licenses, required attribution and change notices.
- `data/`: normalized seed data maintained with the domain contracts.

The first imported track is **Carefree** by **Kevin MacLeod**, [original source](https://incompetech.com/music/royalty-free/index.html?isrc=USUAN1400037), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). It is redistributed unchanged. SVG covers are original procedural geometry generated by `scripts/create-demo-covers.mjs`, CC0 to the extent rights exist. See `licenses.json` for exact records. Do not remove credits when copying an artifact.

Twelve distinct recordings are listed in `scripts/media-sources.json`. Expansion beyond the first track is gated on actual published MP3/seek proof and available LFS quota. The current one-file probe does not claim all twelve binaries or full-demo acceptance.

After `npm ci` and installing Task/LFS, the full flow is:

```text
task ci:tools
task ci:check
task build:demo
task media:pull
task media:verify
task pages:package
task pages:smoke
task pages:preview
```

For the standalone first-file experiment:

```text
task media:pull TRACK_IDS=1 MEDIA_SKIP_SEED=1
task pages:probe
task pages:smoke PAGES_DIR=.pages-probe
task pages:preview PAGES_DIR=.pages-probe
```

In development, `npm run dev:demo` uses Vite middleware at the configured base. In preview/publication, MP3s are ordinary `${BASE_URL}demo/audio/...` files supporting HTTP ranges. They are never imported into JS/CSS or encoded as data URLs. A pointer in place of audio is an error, not a usable recording.

`npm run build` remains the API build. Docker excludes this entire directory, generated publications and media caches while retaining TypeScript/config modules needed for a real build. No demo data or audio belongs in the API output or Nginx application files.
